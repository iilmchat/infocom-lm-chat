1. Цель проекта
Разработать минималистичный симулятор строительства метрополитена для браузера. Игрок управляет растущей сетью линий метро в процедурно генерируемом городе, соединяя станции и перевозя пассажиров. Цель — продержаться как можно дольше, не допустив переполнения станций.

2. Общие требования
Технологии: Чистый JavaScript (ES6+), HTML5 Canvas для рендеринга, CSS для элементов интерфейса.

Платформа: Браузер (десктопная версия).

Управление: Мышь (клики, перетаскивание).

Стиль: Минималистичный, как на картах метро (яркие цвета, простые геометрические фигуры).

3. Функциональные требования (Полный список механик Mini Metro)
3.1. Игровой мир и станции
Станции: Отображаются в виде узлов с простыми геометрическими формами (круг, квадрат, треугольник, ромб и т.д.).

Появление: Новые станции появляются процедурно в случайных местах на карте по мере развития игры.

Пассажиры: На каждой станции генерируются пассажиры. Каждый пассажир хочет попасть на станцию с такой же формой, как и он сам.

Вместимость: Каждая станция имеет ограниченную вместимость. Если она переполняется, игра заканчивается.

3.2. Линии и поезда
Создание линий: Игрок создает линии метро, рисуя их от станции к станции. Линии могут быть перерисованы в любой момент.

Ограничения: Количество линий ограничено. Новые линии можно получить в качестве награды.

Поезда: На каждой линии курсирует поезд. Поезда автоматически перемещаются по линии, забирают и высаживают пассажиров на станциях.

Вагоны: К поездам можно прицеплять дополнительные вагоны для увеличения вместимости.

3.3. Ресурсы и улучшения
Награда за неделю: Каждую игровую "неделю" игрок получает новый локомотив и может выбрать одно из двух предложенных улучшений:

Новая линия (Line): Увеличивает максимальное количество линий (до 7).
Вагон (Carriage): Добавляет дополнительный вагон к любому поезду.
Мост/Тоннель (Bridges/Tunnels): Позволяет прокладывать линии через водные преграды.
Пересадочный узел (Interchanger): Увеличивает вместимость станции и ускоряет пересадку.
3.4. Игровые режимы
Обычный (Normal/Standard): Классический режим с постепенным усложнением. Игра заканчивается при переполнении станции.

Бесконечный (Endless/Zen): Расслабленный режим без поражения, для творческого построения сетей.

Экстремальный (Extreme): Повышенная сложность: новые станции появляются быстрее, а количество линий и поездов ограничено.

3.5. Интерфейс и визуализация
Карта города: Отображение "суши" и "воды", на которой появляются станции.

Счетчик пассажиров: Отображение общего количества перевезенных пассажиров (основной показатель прогресса).

Статистика станций: Визуальное отображение загруженности каждой станции (например, размер или цвет иконки).

Меню улучшений: Всплывающее окно с выбором бонуса в конце каждой недели.

4. Техническая архитектура (Ключевые компоненты)
Для чистого JS-проекта рекомендуется использовать модульный подход (классы).

Game (Ядро игры): Управляет основным циклом (обновление, отрисовка), состояниями (меню, игра, пауза), режимами, счетом и таймером.

City (Город): Генерирует и хранит список станций. Отвечает за появление новых станций.

Station (Станция): Имеет координаты (x, y), тип (форма), список ожидающих пассажиров и текущую загруженность.

Passenger (Пассажир): Имеет тип (форма пункта назначения) и ссылку на станцию назначения.

Network (Сеть): Управляет линиями метро. Проверяет валидность соединений.

Line (Линия): Список станций в порядке следования, ссылка на поезд, цвет.

Train (Поезд): Текущая позиция на линии, направление, список пассажиров в вагонах (вместимость).

Renderer (Рендерер): Вся отрисовка на Canvas: фон, станции, линии, поезда, пассажиры, интерфейс.

InputHandler (Обработчик ввода): Обрабатывает события мыши (клик для выбора, перетаскивание для рисования линий, перетаскивание вагонов между поездами).

5. Поэтапный план реализации (Sprint'ы)
Этап 1: Базовый движок и рендеринг (Спринт 1)
Цель: Создать работающее окно игры с отрисовкой статичных объектов.

Задачи:

Настроить HTML-страницу с элементом <canvas>.
Реализовать класс Game с основным циклом (requestAnimationFrame).
Реализовать класс Renderer для отрисовки фона (сетка или водоем) и базовых фигур (круг, квадрат, треугольник).
Создать класс Station и отрисовать 3 стартовые станции в центре экрана.
Этап 2: Пассажиры и базовая логика (Спринт 2)
Цель: Реализовать появление пассажиров и их визуализацию.

Задачи:

Создать класс Passenger с типом (формой).
В классе Station реализовать генерацию пассажиров (по таймеру). Пассажир появляется со случайным типом, отличным от типа станции.
Модифицировать Renderer для отрисовки пассажиров в виде маленьких фигурок рядом со станцией.
Реализовать простой интерфейс: отображение счета (количество перевезенных пассажиров).
Этап 3: Создание линий и движение поездов (Спринт 3)
Цель: Реализовать основной игровой процесс — рисование линий и движение поездов.

Задачи:

Реализовать в InputHandler логику рисования линии: клик на станции для начала линии, клик на следующей станции для продолжения, двойной клик или клик на пустом месте для завершения.
Создать класс Line, который хранит массив станций и цвет.
Создать класс Train, который хранит ссылку на Line, текущую позицию (индекс станции и прогресс между ними) и направление.
Реализовать логику посадки/высадки пассажиров: когда поезд прибывает на станцию, все пассажиры, чей пункт назначения совпадает с типом станции, выходят (увеличивая счет). Все пассажиры на станции, чей путь лежит через эту линию, заходят в поезд (если есть место).
Этап 4: Улучшения и ресурсы (Спринт 4)
Цель: Добавить систему наград и управления ресурсами.

Задачи:

Внедрить игровой таймер "неделя" (например, 60 секунд реального времени).
По окончании недели останавливать игру и показывать меню выбора улучшений (модальное окно с 2 вариантами).
Реализовать улучшения:
Новая линия: Увеличить maxLines на 1.
Вагон: При клике на поезд добавлять ему +1 к вместимости.
Мост: Увеличить счетчик мостов (пока просто как число).
Пересадочный узел: При клике на станцию увеличить ее вместимость.
Добавить автоматическое добавление нового локомотива каждую неделю.
Этап 5: Рост города и условия поражения (Спринт 5)
Цель: Сделать игру динамичной и добавить "Game Over".

Задачи:

В классе City реализовать процедурную генерацию новых станций. Новая станция появляется в случайном месте на карте, но не слишком близко к существующим.
Реализовать условие поражения: если на любой станции количество пассажиров превышает ее вместимость более чем на 10 секунд.
Добавить экран "Game Over" с отображением финального счета.
Этап 6: Полировка и дополнительные функции (Спринт 6)
Цель: Довести игру до ума.

Задачи:

Реализовать режимы игры (обычный, бесконечный, экстремальный) через настройки в начале.
Добавить возможность перетаскивать поезда с одной линии на другую.
Добавить возможность перетаскивать вагоны между поездами.
Реализовать отрисовку линий в стиле карт метро (прямые горизонтальные, вертикальные и диагональные линии с закруглениями на станциях).
Улучшить визуальную обратную связь: анимация посадки/высадки, подсветка переполненных станций.
Добавить звуковое сопровождение (используя Web Audio API для процедурной генерации звуков).
6. Технические детали реализации
Управление линиями: При рисовании линии, если игрок тянет от существующей станции к новой, линия продлевается. Если кликает на существующую станцию в середине линии, линия разрывается (это сложная, но важная механика).

Переполнение станции: Механика "10 секунд" требует ведения таймера для каждой станции, который сбрасывается, когда поезд забирает пассажиров.

Мосты: Ограниченное количество мостов позволяет прокладывать линии через реки. Это можно реализовать как проверку при создании линии: если отрезок пересекает "воду", требуется 1 мост.

Оптимизация: При большом количестве пассажиров и поездов важно оптимизировать отрисовку на Canvas (например, не перерисовывать статичные линии каждый кадр).

7. Критерии приемки (Definition of Done)
Игра запускается в браузере без ошибок в консоли.

Игрок может создать минимум 3 линии, соединяющие станции.

Поезда автоматически перемещаются по линиям и перевозят пассажиров.

Счет увеличивается, когда пассажир достигает пункта назначения.

Система улучшений работает и выдает награды каждую игровую неделю.

Игра заканчивается при переполнении станции, и показывается финальный счет.

Код соответствует стандартам ES6+, разбит на модули/классы и имеет базовое документирование.

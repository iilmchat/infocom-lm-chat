Промпт для нового чата (продолжение разработки Infocom LM Chat Pro v6.0 → v6.1)
1. О проекте
Название: Infocom LM Chat Pro
Версия: 6.0 (текущая, готовимся к 6.1)
Тип: Клиентская часть SPA-чата с AI-интеграцией (LM Studio), многопользовательским режимом (Long Polling), RAG, администрированием, аналитикой, играми и приватными чатами.

Технологии:

Чистый JavaScript (ES-модули)

HTML5, CSS3 (поддержка трёх тем: тёмная, светлая, monokai)

Серверная часть: .NET Core 3.1 API + MS SQL Server (не входит в этот репозиторий)

Сборка: без сборщика, используются type="module" и загрузка скриптов через теги <script> для библиотек.

Архитектура:

Шина событий EventBus для слабосвязанной коммуникации между модулями.

Менеджеры состояния: SessionManager, MultiUserManager, RAGManager, AssistantManager, AchievementManager, NotificationManager и др.

Сервисы: ApiService (HTTP-клиент), AuthService, MarkdownService, LongPollingClient.

UI-компоненты: Modal, Toast, DropZone, VirtualScroll и др.

SPA-роутинг (Router на History API) – реализован в v6.0.

Модульная архитектура: основные разделы вынесены в отдельные модули (чат, приватные чаты, админка, игры, профиль) с динамической загрузкой.

3. Задачи для следующего этапа (v6.1)
Мы планируем следующие улучшения. Важно реализовать их аккуратно, не нарушая существующую архитектуру, с сохранением стиля кода (ES-модули, комментарии, чистота).

Задача 5: Обновление стилей кнопок (скругление, тематические цвета)
Цель: Сделать все кнопки визуально единообразными, с скруглением и тематическими цветами.

Реализация:

В themes.css добавить CSS-переменные для кнопок:
--btn-border-radius, --btn-primary-bg, --btn-primary-hover, --btn-secondary-bg, --btn-danger-bg и т.д.

В main.css или отдельном файле определить классы .btn, .btn-primary, .btn-secondary, .btn-danger, .btn-success, .btn-warning со скруглением и цветами.

Применить эти классы ко всем кнопкам в HTML и динамически создаваемым кнопкам в JS (заменить inline-стили на классы).

Проверить все модальные окна, формы, панели.

Задача 6: Модуль аватаров и идентификации (AvatarService)
Цель: Улучшить визуальную идентификацию пользователей, дать возможность загружать собственные аватарки и генерировать их автоматически.

Реализация:

Создать AvatarService в src/services/avatar-service.js.

Поддерживать три режима:

Эмодзи (как сейчас) – выбирается из набора или вводится вручную.
Генерация на основе имени – использовать canvas для рисования инициалов на цветном фоне (или библиотеку jdenticon, dicebear).
Загрузка собственного изображения – через <input type="file">, сжатие (canvas) до 100×100 px, сохранение в формате DataURL в localStorage (или на сервер).
В профиле добавить переключатель типа аватара и предпросмотр.

При сохранении профиля сохранять выбранный тип и данные аватара в объекте пользователя (добавить поля avatarType и avatarData).

Интегрировать с MultiUserManager и ProfileModule.

Задача 8: Интернационализация (i18n)
Цель: Поддержка нескольких языков (русский, английский).

Реализация:

Создать модуль i18n в src/services/i18n.js с функциями setLanguage, t(key, params).

Создать файлы переводов locales/ru.json и locales/en.json (можно хранить в JS-объектах).

Определить язык по браузеру (navigator.language) или сохранять выбор пользователя в localStorage.

Заменить все статические строки в коде (в HTML и JS) на вызовы t('key').

Добавить переключатель языка в профиль или в шапку.

Задача 10: Экспорт/импорт данных пользователя
Цель: Позволить пользователю скачать все свои данные (сообщения, настройки, достижения, RAG-документы) в одном JSON-файле и восстановить их при необходимости.

Реализация:

В ProfileModule (или в отдельном модальном окне) добавить кнопки «Экспорт данных» и «Импорт данных».

Экспорт: собрать данные из localStorage: сессии (SessionManager), настройки (server_config, admin_settings, chat_theme), достижения (achievements), RAG-тексты (только чанки без эмбеддингов), рабочие пространства (workspaces). Сформировать объект и скачать как user_data_YYYY-MM-DD.json.

Импорт: загрузить JSON, провалидировать структуру (проверить наличие обязательных полей), затем восстановить данные через соответствующие менеджеры (с возможностью перезаписи или слияния).

Добавить подтверждение перед импортом (предупреждение о перезаписи).

Доработка модуля приватных чатов (PrivateChatModule)
Цель: Добавить недостающие функции и улучшить UX.

Реализация:

Упоминания – при вводе @ показывать список пользователей, вставлять упоминания в сообщение, отправлять уведомления упомянутым.

Интеграция с уведомлениями – при получении нового сообщения в приватном чате создавать уведомление через NotificationManager.

Поиск по сообщениям – добавить поле поиска в шапке чата, фильтровать сообщения по тексту.

Пагинация – уже есть, но можно улучшить (бесконечный скролл).

Стили – убедиться, что private-chat.css полностью применяется, добавить недостающие стили (например, для сообщений, реакций, закреплений).

Доработка модуля профиля (ProfileModule)
Цель: Сделать страницу профиля полноценной, без использования модалки как fallback.

Реализация:

В showProfile() в app.js загружать ProfileModule и отображать его контейнер, не открывая ProfileModal.

Перенести всю логику редактирования профиля из ProfileModal в ProfileModule (или оставить ProfileModal только для быстрого доступа из чата, а страницу профиля сделать отдельной).

Добавить в профиль отображение статистики (количество сообщений, достижений, файлов и т.д.).

Добавить кнопки экспорта/импорта данных (Задача 10).

4. Правила комментирования и версионирования
Все новые блоки кода помечаются /* Добавлено в 6.1 */.

Изменённые блоки помечаются /* Изменено в 6.1 */ с кратким описанием.

Удалённый код не удаляется, а закомментирован и помечен /* Удалено в 6.1 */.

В начале каждого изменённого файла добавляется комментарий с версией и списком изменений (если они глобальные).

Версия в config.js обновляется до 6.1.

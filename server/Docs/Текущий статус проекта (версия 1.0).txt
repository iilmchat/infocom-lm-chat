Итоги работы и промпт для нового чата с DeepSeek
Текущий статус проекта (версия 1.0)
Мы разработали серверную часть веб-приложения «Менеджер ИТ-проектов» на .NET Core 3.1 с MS SQL Server.
Проект содержит:

Модели данных: User, Session, Project, ProjectOwner, Document.

Аутентификацию на основе токенов (GUID), хранящихся в БД, с кастомным AuthMiddleware.

Хэширование паролей через SHA256 (без внешних зависимостей).

CRUDL операции с проектами:

Создание (только имя), редактирование, удаление, закрытие.

Контроль доступа: владельцы проекта и глобальный администратор.

Управление владельцами (добавление/удаление с защитой от удаления последнего).

Версионирование документов с последовательной доступностью типов (ИД → Проект → ТТ → ПиМ ПСИ; ЦБИ – свободно).

Создание черновиков, редактирование только черновиков, принятие версии (становится активной), удаление черновиков.

Запрет операций для закрытых проектов.

Глобальную обработку ошибок, логирование, CORS.

Модульную структуру с интерфейсами сервисов.

Код полностью задокументирован на русском языке (комментарии в моделях, методах, DTO, контроллерах).
Проект готов к запуску после создания миграций и обновления БД.

Задачи для версии 1.1 (следующий шаг)

Разработать HTML+JS клиент для ручного тестирования API (спринт 5):

Одностраничное приложение с авторизацией (ввод токена, сохранение в localStorage).

Дизайн аналогичен предоставленному примеру (тёмная тема), но адаптированный под наш API.

Финальное тестирование и релиз (спринт 6) – будет выполнен после реализации пунктов 1 и 2.

Технологии и ограничения
Сервер: .NET Core 3.1, Entity Framework Core 3.1, MS SQL Server.

Клиент: чистый HTML + CSS + JavaScript (без фреймворков).

Аутентификация: Bearer-токен (передаётся в заголовке Authorization).

Все HTTP-методы: только GET и POST (без PUT, DELETE).
Действия типа «удалить» и «обновить» реализованы через POST с соответствующими маршрутами (например, /update, /delete, /accept).

Код должен быть прокомментирован на русском языке (все классы, методы, сложные участки).

Проект не использует Swagger – документация будет заменена тестовым клиентом.
